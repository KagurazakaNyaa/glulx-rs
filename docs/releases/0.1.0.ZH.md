# glulx-rs 0.1.0

[English](0.1.0.md) | [中文](0.1.0.ZH.md)

glulx-rs 首个公开版本在同一个可执行文件中提供 Glulx 虚拟机、图形播放器和交互式终端播放器。使用发行包无需安装 Rust。

## 已包含功能

- Glulx 3.1.3 与 Glk 0.7.6：整数和浮点指令、Unicode、堆分配、Inform 加速函数 1–13、可移植 IFZS 存档及多级 undo。
- 桌面窗口、样式文本与网格、行内/边栏图片、图形、超链接、字体及可用时的真实 light 字重、文件提示、历史记录和自动会话恢复。
- AIFF/OGG/MP3 音频、MOD/XM/S3M/IT 音乐，以及使用共享 AIFF 乐器的旧版 SONG 格式；支持重复、暂停、渐变和完成事件。
- 内嵌或独立 Blorb 资源、显式散装资源目录、故事身份检查、封面与资源文字说明。桌面会话保留资源内容，原始文件删除后仍可恢复。
- 交互式 `--headless` TTY 播放，包含状态/网格窗口、预填编辑、定时取消和即时字符输入。管道输入输出保留独立的自动化协议。

## 下载与运行

每个二进制发行包包含可执行文件和 AGPL-3.0-only 许可证。`SHA256SUMS` 提供各二进制发行包的 SHA-256 校验值。

| 平台 | 压缩包 | 构建基线 |
| --- | --- | --- |
| Linux x86-64 | `glulx-rs-v0.1.0-x86_64-unknown-linux-gnu.tar.gz` | Ubuntu 22.04、glibc 2.35 |
| macOS Intel | `glulx-rs-v0.1.0-x86_64-apple-darwin.tar.gz` | macOS 13.0 部署目标；macOS 26 Intel CI |
| macOS Apple Silicon | `glulx-rs-v0.1.0-aarch64-apple-darwin.tar.gz` | macOS 13.0 部署目标；`macos-latest` CI |
| Windows x86-64 | `glulx-rs-v0.1.0-x86_64-pc-windows-msvc.zip` | Windows 10+ 目标；`windows-latest` CI |

Linux 使用系统 OpenGL、X11/Wayland 和 ALSA 库。Windows 发行包静态链接 C 运行时，减少对额外安装 Visual C++ Redistributable 的依赖。macOS 和 Windows 二进制未使用开发者证书签名，macOS 二进制也未进行 notarization。macOS 下载包包含可执行文件，不是 `.app` 应用包。上述构建基线不代表每个系统版本都已通过实机测试。

解压后运行 `glulx-rs`（Windows 为 `glulx-rs.exe`），在播放器中打开故事。命令行示例：

```sh
./glulx-rs story.gblorb
./glulx-rs --resources media.blorb story.ulx
./glulx-rs --headless story.ulx
```

可使用 Linux 的 `sha256sum`、macOS 的 `shasum -a 256` 或 Windows PowerShell 的 `Get-FileHash -Algorithm SHA256`，对照 `SHA256SUMS` 核验已下载的压缩包。

## 验证情况与限制

发布候选已通过 181 个 Rust 测试（179 个库测试、2 个 CLI 测试）、Clippy、release 构建及全部 10 项参考检查。参考验证涵盖 92 个 Glulxercise 段落、Unicode/资源流转录、Inform 加速函数，以及与 Glulxe 双向互读 Adventure 存档。Linux PTY 和 Xvfb/软件 OpenGL 下的 GUI 检查均已通过，包括外部资源、SONG 播放与会话恢复，以及实际 light 字体呈现。

发布工作流要求四个目标平台的测试、Clippy、release 构建和待打包可执行文件的原生 `--help` 冒烟检查全部成功，并通过额外 `ubuntu-latest` 任务的测试和 Clippy，Linux/macOS 还对实际 release 可执行文件运行终端验收，随后才发布压缩包。Linux 发行包仍在 Ubuntu 22.04 构建，以保留 glibc 兼容基线。Windows/macOS 实机 GUI、长篇游戏完整流程、所有媒体编码及实体声卡输出尚未验证。本版本不宣称已经穷尽验证全部规范行为。

VM 内存上限为 256 MiB；undo 最多保留 16 个状态，使用 64 MiB 估算预算。图形和音频能力取决于宿主。SONG 样本转换为 16 位单声道，其结构和解码样本上限分别为 1 MiB、32 MiB。完整范围和复现方法见[兼容性说明](../compatibility.ZH.md)、[规范清单](../glulx-spec-checklist.ZH.md)及[验收记录](../glulx-validation.ZH.md)。
