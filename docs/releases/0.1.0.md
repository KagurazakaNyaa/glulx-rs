# glulx-rs 0.1.0

[English](0.1.0.md) | [中文](0.1.0.ZH.md)

The first public release of glulx-rs includes a Glulx virtual machine, graphical
player and interactive terminal player in one executable. No Rust installation
is needed to run the packaged binaries.

## Included

- Glulx 3.1.3 and Glk 0.7.6: integer and floating-point instructions, Unicode,
  heap allocation, Inform acceleration functions 1–13, portable IFZS saves and
  multiple undo states.
- Desktop windows, styled text and grids, inline/margin images, graphics,
  hyperlinks, fonts including real light faces when available, file prompts,
  scrollback and automatic session restoration.
- AIFF/OGG/MP3 audio, MOD/XM/S3M/IT music and legacy SONG resources with shared
  AIFF instruments; repetition, pause, fades and completion events.
- Embedded or separate Blorb resources, explicit loose resource directories,
  story identity checks, cover art and textual resource descriptions. Desktop
  sessions retain resource content even if the original files are removed.
- Interactive `--headless` TTY playback with status/grid windows, prefilled
  editing, timed cancellation and immediate character input. Piped input/output
  retains a separate automation protocol.

## Downloads

Each binary archive contains the executable and the AGPL-3.0-only license. `SHA256SUMS`
contains the SHA-256 digest of each binary archive.

| Platform | Archive | Build baseline |
| --- | --- | --- |
| Linux x86-64 | `glulx-rs-v0.1.0-x86_64-unknown-linux-gnu.tar.gz` | Ubuntu 22.04, glibc 2.35 |
| macOS Intel | `glulx-rs-v0.1.0-x86_64-apple-darwin.tar.gz` | macOS 13.0 deployment target; macOS 26 Intel CI |
| macOS Apple Silicon | `glulx-rs-v0.1.0-aarch64-apple-darwin.tar.gz` | macOS 13.0 deployment target; `macos-latest` CI |
| Windows x86-64 | `glulx-rs-v0.1.0-x86_64-pc-windows-msvc.zip` | Windows 10+ target; `windows-latest` CI |

Linux uses the system OpenGL, X11/Wayland and ALSA libraries. The Windows package
statically links the C runtime to reduce reliance on a separate Visual C++
Redistributable installation. macOS and Windows
binaries are not signed with developer certificates; macOS binaries are not
notarized. The macOS downloads contain an executable, not an `.app` bundle.
The build baselines are not a claim of on-device testing on every OS version.

Extract the archive and run `glulx-rs` (`glulx-rs.exe` on Windows), then open a
story in the player. Command-line examples:

```sh
./glulx-rs story.gblorb
./glulx-rs --resources media.blorb story.ulx
./glulx-rs --headless story.ulx
```

Compare the downloaded archive against `SHA256SUMS` using `sha256sum` on Linux,
`shasum -a 256` on macOS, or PowerShell `Get-FileHash -Algorithm SHA256` on Windows.

## Validation and limits

The release candidate passed 181 Rust tests (179 library and 2 CLI), Clippy,
the release build and all ten reference checks. Reference validation includes
92 Glulxercise sections, Unicode/resource-stream transcripts, Inform acceleration
and bidirectional Adventure saves with Glulxe. Linux PTY checks and GUI checks
under Xvfb/software OpenGL passed, including external resources, SONG playback
and session restoration, and actual light-font rendering.

The release workflow requires tests, Clippy, release builds and a native `--help`
smoke check of the packaged executable on all four targets
before it publishes archives. Linux/macOS also run the terminal suite against
the packaged release executable. An additional `ubuntu-latest` job checks tests and
Clippy; the Linux package is built on Ubuntu 22.04 to retain its glibc baseline.
Windows/macOS on-device GUI behavior, complete
long-game walkthroughs, every media encoding and physical sound-card output
remain unverified. This release does not claim exhaustive specification conformance.

VM memory is capped at 256 MiB; undo keeps up to 16 states within a 64 MiB
estimated budget. Graphics/audio capabilities depend on the host. SONG samples
are converted to 16-bit mono; its structure and decoded-sample limits are 1 MiB
and 32 MiB respectively. See the [compatibility details](../compatibility.md),
[specification checklist](../glulx-spec-checklist.md) and
[validation record](../glulx-validation.md) for the full scope and reproducible checks.
